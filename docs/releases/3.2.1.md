# Soduto 3.2.1 (38)

This build fixes copied images and files that stopped reaching other devices after Soduto had been running for a while, while text kept working.

## Changes

- **Clipboard images and files:** each upload reserves one of 26 ports while it waits for the other device. An upload that ended because its connection closed, for example after sleep or a reconnect, never gave its port back. Once all 26 were taken, every image and file failed to send until Soduto was restarted. Uploads now release their port however they end. A regression test covers uploads that are closed, cancelled or discarded.

Unchanged from build 37:

- **Release publishing:** an optional manual workflow input publishes only after both test jobs pass. The workflow verifies the ZIP and build manifest attestations, creates a unique tag at the built commit, and uploads the exact CI package. Existing tags and releases cannot be replaced.
- **Device menu:** colored device-type icons, connection status, reported battery/network details, and connected devices first. Exact presentation follows your macOS version.
- **Diagnostics:** logging is off by default. Diagnostics is above Quit, with a separator above Reconnect All Devices.
- **Connection improvements and bugfixes:** sleep/Wi-Fi recovery, protocol 7/8 pairing, certificate verification, clipboard freshness, and legacy Keychain signing fixes.
- **Clipboard:** text, images, and one regular file up to 50 MiB with compatible peers. Image/file sync needs `kdeconnect.clipboard.file`. Official GSConnect supports text only; see the [GSConnect fork](https://github.com/hidoba/gnome-shell-extension-gsconnect/tree/hidoba).

## Install

Download the universal macOS ZIP and its `.sha256` file, quit Soduto, and replace the app in Applications. Requires macOS 14 or newer; supports Apple Silicon and Intel. The app is ad-hoc signed and unnotarized. Existing pairings and preferences are preserved. Updating may require normal Keychain approval.

## Validation

The workflow runs the application checks, the release-pipeline checks, and a separate Keychain/TLS job that verifies 600 signatures with a legacy key and the new upload port tests. It builds the universal Release app and extensions, verifies the complete app signature, and checks signed build provenance before publishing. Automated checks do not establish end-to-end compatibility with a physical Ubuntu peer.
