# Soduto 3.2.1 (29)

An unsigned, unnotarized **pre-release** of the hidoba fork for **macOS 14+**.
The app is universal: **Apple Silicon (`arm64`) and Intel (`x86_64`)**.

**Build 29 replaces build 28 with one app and opt-in log writing, off by default.**

This combines upstream `fix/network-reliability` (`ca7db3a`) and
`feat/refine-services` (`afcc62d`), with additional clipboard, pairing, and recovery
fixes and a small connection badge over the menu bar icon.

## Changes

- **Clipboard:** retain offline-copy freshness, protect non-text copies, preserve
  identical pasteboard content, prevent multi-peer replay loops, forward fresh
  generations through hubs, and discard stale queued copies on reconnect.
- **Pairing:** validate protocol 8 timestamps and TLS certificates, retain protocol
  7 support, avoid duplicate confirmation loops, cancel interrupted requests, and
  prevent competing sockets or stale UI results from replacing an active prompt.
- **Connection recovery:** fix callback ordering and the initial service handoff;
  reset old connections after wake/network changes, refresh capabilities after
  reconnects, and prevent retired sockets from applying clipboard or unpair packets.
  Connection initialization has a **10-second deadline** with diagnostic phases.
- **Log writing, off by default:** use **Preferences → Diagnostics → Write diagnostic
  logs** or **Diagnostics → Write diagnostic logs**. The controls stay synchronized
  and remember the choice. Turning it off drains pending writes and closes the
  file, preserving older logs. The Diagnostics menu is directly above Quit. Export,
  open-log-folder and packet-logging controls disable while writing is off;
  Reconnect All Devices remains available. Ordinary Console logging is separate.
- **Diagnostics:** when writing is enabled, export a ZIP with a runtime snapshot and a persistent journal
  limited to **four 5 MiB files**. Packet metadata, connection lifecycle, pairing,
  and clipboard decisions are logged; packet bodies, clipboard text, keys, and
  other private payloads are excluded. No logs are uploaded.
- **Menu bar:** a small badge over the icon shows **1–99**, **99+**, or **×** when
  no paired devices are connected. The original square width is preserved; hover
  for the full count. Light/dark appearances and the accessibility label are supported.
- **Fork identity:** bundle ID `com.hidoba.Soduto`, separate preferences/keychain
  identities, and manual fork updates with upstream Sparkle updates disabled.

## Download

Download `Soduto-3.2.1-29-macos-universal.zip` and its matching `.sha256` file.
In the download directory, run:

```sh
shasum -a 256 -c Soduto-3.2.1-29-macos-universal.zip.sha256
```

The SHA-256 is:

```text
353317985e22e28e4440218200e3f4ffa1c39abad4d716de49d1ae45e03b5c31
```

Extract the ZIP to get `Soduto.app`. The app is unsigned and not notarized;
macOS may block it. A development-signed build can be made with Xcode and your
own Apple Developer team. Quit the running copy and other Mac KDE Connect clients
before updating or testing. A first install pairs as a new device; updates of this
fork retain the existing pairing and preferences.

## Remaining validation

The automated scenarios use fake clipboard, transport, certificate storage, and UI
boundaries. Actual Ubuntu GNOME/Wayland clipboard and pairing, repeated sleep/wake,
and Wi-Fi reconnection tests remain pending, including the reported KDE Connect
25.12.3 setup. Protocol 7/8 checks do not establish that every inherited service
works with every KDE Connect client.

For a failure, enable **Write diagnostic logs**, reproduce the issue and use
**Diagnostics → Export Diagnostic Bundle…** before choosing **Reconnect All Devices**.
You can turn log writing off afterwards. This release focuses on clipboard, pairing, and their
shared transport paths; unrelated service review findings remain outside this fix set.
