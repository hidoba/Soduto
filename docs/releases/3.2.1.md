# Soduto 3.2.1 (37)

GitHub Actions now builds, tests, and publishes releases automatically when requested. Releases include a signed build attestation so you can verify the download against its source commit and workflow. The app keeps the native device menu, clipboard features, and connection fixes from build 36.

## Changes

- **Release publishing:** an optional manual workflow input publishes only after both test jobs pass. The workflow verifies the ZIP and build manifest attestations, creates a unique tag at the built commit, and uploads the exact CI package. Existing tags and releases cannot be replaced.
- **Device menu:** colored device-type icons, connection status, reported battery/network details, and connected devices first. Exact presentation follows your macOS version.
- **Diagnostics:** logging is off by default. Diagnostics is above Quit, with a separator above Reconnect All Devices.
- **Connection improvements and bugfixes:** sleep/Wi-Fi recovery, protocol 7/8 pairing, certificate verification, clipboard freshness, and legacy Keychain signing fixes.
- **Clipboard:** text, images, and one regular file up to 50 MiB with compatible peers. Image/file sync needs `kdeconnect.clipboard.file`. Official GSConnect supports text only; see the [GSConnect fork](https://github.com/hidoba/gnome-shell-extension-gsconnect/tree/hidoba). Ubuntu GNOME/Wayland image/file sync still needs real-device validation.

## Install

Download the universal macOS ZIP and its `.sha256` file, quit Soduto, and replace the app in Applications. Requires macOS 14 or newer; supports Apple Silicon and Intel. The app is ad-hoc signed and unnotarized. Existing pairings and preferences are preserved. Updating may require normal Keychain approval.

## Validation

The workflow runs 122 application checks, six release-pipeline checks, and a separate regression verifying 600 signatures with a legacy key. It builds the universal Release app and extensions, verifies the complete app signature, and checks signed build provenance before publishing. Automated checks do not establish end-to-end compatibility with a physical Ubuntu peer.
