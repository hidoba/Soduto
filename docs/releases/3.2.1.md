# Soduto 3.2.1 (34)

Build 34 fixes all four findings from the build-33 clipboard review: stale cache
pruning, superseded outgoing uploads, files incorrectly required to decode as
bitmaps, and identical pictures retaining an obsolete filename. Image, single-file
and text clipboard synchronization remain available with the existing direction
settings. Copy while connected, then paste on the other computer.

This is an **ad-hoc-signed, unnotarized development release** for **macOS 14+**,
with a universal Apple Silicon (`arm64`) and Intel (`x86_64`) executable.

## Changes

- **Build 34 review fixes:** cancel superseded outgoing image/file uploads on a
  new copy, accepted remote content, peer disconnect, or disabling outgoing sharing.
  A duplicate incoming file cancels only an upload to its sender, preserving
  transfers to other peers. Completed uploads leave cancellation tracking.
- Stage received files without evicting anything; publish only after checking
  clipboard and connection freshness. Prune after a successful clipboard update,
  checking the live selection before each removal. An obsolete background transfer
  cannot delete an older cached file restored to the clipboard.
- Preserve every unmarked KDE payload as its original file, including SVGs and
  images exceeding the bitmap pixel limit. Add an optional PNG preview when it can
  be decoded within the image limits. Require bitmap decoding only for explicitly
  image-only payloads from this fork.
- Include safe filename and original bytes in file duplicate detection. Receiving
  identical pixels as `second.png` after `first.png` updates the copied filename
  and relays the original file. Explicit bitmap generations still compare pixels.
- **Image clipboard:** send macOS PNG/TIFF clipboard images as PNG and receive
  image payloads through KDE Connect's `kdeconnect.clipboard.file` extension.
  The extension is present in both KDE Connect 25.12.3 and 26.08.2. Image content
  takes priority over alternate text. Explicit bitmap generations use pixel
  comparisons to prevent duplicate echoes across PNG/TIFF encodings; original
  KDE files retain their filename and bytes. Intentional later copies can sync again.
- **File clipboard:** transfer one regular file of up to 50 MiB, including empty
  files, with its original safe basename. Copy in Finder and paste on the
  connected KDE computer, or copy on KDE and paste in Finder. Folders, symlinks
  and multiple-file selections are ignored. Uploads capture an immutable snapshot;
  the original is never moved or modified. Received files are not opened.
  Private cache directories use 0700 permissions and files use 0600. Entries
  older than 24 hours are pruned after new content is accepted, with a 200 MiB budget;
  the current clipboard file is protected. Image files within the image limits also expose PNG image data.
  This clipboard cache operates separately from diagnostic log writing.
- **Freshness and limits:** image conversion runs off the main thread. Incoming
  transfers have a 35-second deadline and limits of 50 MiB encoded and
  16,777,216 decoded pixels for bitmap conversion/previews. Original files still
  transfer up to 50 MiB without a bitmap preview. Unknown sizes, malformed explicit
  bitmap payloads and incomplete transfers are rejected. New copies, newer packets and disconnects invalidate
  pending transfers, including a disconnect/reconnect during decoding.
  Images, files and consumed upload streams are not replayed after reconnecting.
  KDE's temporary file URL in a reconnect handshake cannot replace a local image
  or file with path text. Images and files synchronize on copy while connected.
  Folders and multi-file selections are outside this clipboard feature.
- **Text clipboard:** retain offline-copy freshness, protect unsupported formats,
  preserve identical content, converge simultaneous edits and stop multi-peer
  replay loops. Ordinary KDE Connect packets remain live edits despite clock skew.
- **Pairing and recovery:** retain protocol 7/8 pairing, certificate verification,
  v8 timestamp validation, duplicate-confirmation suppression and stale-socket/UI
  protection. Wake/network changes reset stale connections. Initialization has a
  10-second deadline, with its last phase recorded.
- **Keychain:** retain the legacy-key export-loop fix and complete app-bundle
  sealing from builds 31/32. Existing identities, pairings and access controls
  are preserved. TLS uses public-certificate metadata and raw Security signing,
  without private-key export. Access denial suspends automatic signing until
  Reconnect All Devices or restart; temporary errors can recover after unlock.
  New keys have the readable name **Soduto Device Identity**; old keys can still
  display `<key>`. Replacing this development-signed app can require normal
  Keychain signing approval again. Build 32's Always Allow approval was verified
  across a restart of that unchanged binary; that observation does not establish
  approval for this new binary. There is no Developer ID signing or notarization.
- **Diagnostics, off by default:** enable **Write diagnostic logs** in Preferences
  or the Diagnostics menu, directly above Quit. Both controls share the saved
  setting. Image and file events record sends, receives, apply/ignore decisions,
  cancellations, timeouts and failures. Logs contain metadata, never image
  contents, filenames or fingerprints. Journal retention is four 5 MiB files;
  no logs are uploaded. Export/open-log/packet-tracing actions disable while
  writing is off; Reconnect All Devices stays available.
- **Menu bar:** retain the small badge over the icon: 1–99 connected paired
  devices, 99+, or × for none. The tooltip provides the full count.
- **Fork identity:** retain bundle ID `com.hidoba.Soduto` and manual updates,
  with upstream automatic updates disabled. This fork combines upstream
  `fix/network-reliability` (`ca7db3a`) and `feat/refine-services` (`afcc62d`).

## Validation

**117 checks pass** and the complete universal Release app/extension build succeeds. The archive passes strict signature verification for both architectures.

| Suite | Count |

The clipboard suite compiles the actual service and image codec. It covers image
capabilities and direction switches, PNG/TIFF normalization, transparency,
orientation, malformed/truncated/oversized payloads, timeouts, stale completions,
rapid copies, reconnect URL handling, overlapping generations, and mixed text/image relay meshes.
A native AppKit test confirms that a received PNG is recognized as an image on a
unique private pasteboard. The user's general pasteboard is untouched by tests.
File tests cover original names and immutable snapshots, safe private cache files,
empty-file packet framing, unsupported sources, duplicate suppression, cancellation,
direction switches, native file/image representations, generation ordering, expiry
and disk budget enforcement. Thirteen new scenarios reproduce the build-33 review
findings and verify their fixes: live clipboard protection during cache eviction,
original filenames/encodings, SVG and 20-megapixel files, and outgoing upload
cancellation on newer copies, remote content, disconnect, disable and shutdown.
A duplicate header preserves uploads to other peers and completed uploads leave
tracking. Transport tests also verify that refused streams
are discarded instead of queued.

Keychain/TLS tests use isolated temporary keychains and loopback sockets,
including legacy export-protected and nonexportable keys, TLS 1.2/1.3 mutual
verification, six RSA signing schemes, reconnects, denial suppression and temporary
error recovery. A separate native test verifies 600 cross-process legacy-key
signatures. Tests do not change login Keychain permissions.

## Real-device validation

Image/file wire-format compatibility has been checked against the official
[KDE Connect 25.12.3 implementation](https://github.com/KDE/kdeconnect-kde/blob/v25.12.3/plugins/clipboard/clipboardplugin.cpp)
and [26.08.2 implementation](https://github.com/KDE/kdeconnect-kde/blob/v26.08.2/plugins/clipboard/clipboardplugin.cpp).
The reported Ubuntu GNOME/Wayland computer with KDE Connect 25.12.3 still needs
end-to-end testing. KDE Connect exposes received images on Linux as temporary file
URLs, so whether they paste as an image or attachment depends on the target app
and desktop clipboard integration. Test a fresh image and one regular file in each direction
while connected. Repeated sleep/wake and Wi-Fi recovery also remain real-device
validation cases.

If something fails, enable **Write diagnostic logs**, reproduce the issue, and
use **Diagnostics → Export Diagnostic Bundle…** before Reconnect All Devices.
Turn writing off afterwards if desired. This release focuses on clipboard,
pairing and their shared transport paths.
